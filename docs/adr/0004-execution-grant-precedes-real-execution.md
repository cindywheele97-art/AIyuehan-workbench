# Execution Grant precedes real execution

Runtime role descriptions and logical identities do not constrain operating-system access, credentials, mounts or network egress.

No Workbench-managed dynamic task dispatch or Projection mutation may begin without a Workspace-scoped, attempt-bound, time-limited Execution Grant and qualified Runtime Isolation Profile. GOV-0 development and judgment commands through M4 run under an external-authority Bootstrap Development Envelope that cannot itself dispatch work through an External Runtime Provider, deploy, touch customer resources, or count as capability proof. M0-Q is the first dynamic upstream qualification and requires both the external development envelope for the operator and a product Grant for the managed effect.

Consequences: M-1 is static only; M0-Q and every later managed external effect use a product Grant; Execution Grant derives scope from canonical Execution Attempt and Purpose records. A minimum-privilege database routine atomically claims the Grant/use budget and prepares the External Effect before an effect worker can send; effect workers cannot update Grants or access Authority credentials. Rejected alternatives were a permanent bootstrap exception, cross-process claim-then-prepare, caller-supplied scope, or shared daemon credentials. Revisit only if an external executor provides independently verified equal-or-stronger isolation and attestation.
